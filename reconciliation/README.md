# Process Catalog Reconciliation (CR-BP-15-IMP)

**CR-BP-15-IMP Phase 1 (this PR); CR-BP-15 §6 / §7.**

The reconciliation directory hosts the artefacts that drive
CR-BP-15-IMP Phases 1-7: the inventory of every canonical record
as-at CR-BP-14 implementation, the immutable baseline that freezes
those records, and the per-tranche disposition register that
CR-BP-15-IMP Phases 3-7 introduce.

## Layout

```
reconciliation/
├── README.md                         # this file
├── inventory.yaml                    # per-record metadata + raw findings
├── baseline/
│   └── v1.yaml                       # immutable SHA-256 snapshot
├── dispositions/                     # CR-BP-15-IMP Phases 3..7 (later PRs)
│   ├── phase-3.yaml
│   ├── phase-4.yaml
│   └── ...
└── diffs/                            # CR-BP-15-IMP Phase 7 outputs (later)
    └── ...
```

`reports/` (top-level) hosts machine-readable reconciliation
reports generated by `scripts/build_inventory.py` and future
tranche scripts.

## Phase 1: inventory

`reconciliation/inventory.yaml` enumerates every record in the
canonical catalog at the moment CR-BP-14 was declared Implemented:

- 18 Business Processes (L2);
- 10 Process Groups (L1);
- 10 Process Contexts;
- 4 Change Requests (CR-BP-14, CR-BP-15, CR-BP-15-IMP, CR-BP-16).

Each record carries:

- `id`, `name`, `type`, `path`;
- `process_intent` and `process_classification` where applicable;
- `legacy_findings`: the raw BP-SEM findings on that record
  (legacy intent vocabulary; legacy scalar `process_context`;
  missing canonical `context:` block; legacy `process_audience`;
  missing `process_specialization`).

The inventory is reproducible: `python scripts/build_inventory.py`
rebuilds it deterministically from `entities/`, `contexts/` and
`change-requests/`. The script's `--self-test --strict` mode
asserts byte-identity with the committed file.

## Phase 2: baseline

`reconciliation/baseline/v1.yaml` is the immutable snapshot that
freezes the canonical catalog at the same moment. Every record
carries:

- `id`, `type`, `path`;
- `sha256`: the SHA-256 of the file's bytes at baseline time.

Future tranches diff their changes against this baseline. Any
record whose SHA-256 changes between baseline and a subsequent
tranche is recorded in a per-tranche diff (introduced in
CR-BP-15-IMP Phase 7) so the reconciliation gate can prove
exactly which bytes were touched.

## STRUCT conformance (decision D6)

The repository gained two top-level directories under this PR:
`reconciliation/` and `reports/`. To guard against typos (e.g.
`reconcilliation/`) shadowing a real directory, the CR-BP-15-IMP
Phase 1 PR introduces `scripts/check_struct.py` (STRUCT
conformance). STRUCT is intentionally permissive: the
catalogue's contracts own schema integrity; STRUCT only flags
unrecognised top-level entries. The check is wired into CI as an
advisory step (non-blocking) so existing reconciliations are not
disrupted.
